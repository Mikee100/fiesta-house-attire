> and JSON-LD now point at the subdomain. The migration steps below are kept

> env var (falls back to `https://app.fiestahouseattire.com`). **When the new

Goal: the new React app takes over `fiestahouseattire.com`, replacing the old
WordPress site, **without losing the Google rankings WordPress has built up**.

## What was found (diagnosis, July 2026)

1. **Two live sites.** Old WordPress at `fiestahouseattire.com` (indexed, ranking,
   Search Console–verified). New app at `app.fiestahouseattire.com` (nearly
   invisible to Google: raw HTML is an empty shell).
2. **Prerender pipeline broken.** `npm run build` runs `scripts/prerender.mjs`
   (puppeteer), but the committed `dist/` shows it captured pages *before* React
   rendered: no meta tags, no headings, no text. And production isn't serving
   prerendered files anyway.
3. **Config assumed the apex domain.** robots.txt, sitemap.xml, and canonicals all
   point at `fiestahouseattire.com` — wrong while the app sits on `app.`, correct
   after migration. No changes needed there.
4. **OG image pointed at a WordPress upload URL** — would break when WordPress
   dies. Now fixed (self-hosted `/og-image.jpg`).

## What was changed in this repo

- `vercel.json` — **33 permanent (301) redirects** mapping every known WordPress
  URL (portfolio slugs, `/blog-2`, `/contact-us`, `/gowns-for-hire`,
  `/wp-content/*`, etc.) to the app's equivalent pages. This is what carries the
  old rankings over.
- `index.html` — static meta description + **LocalBusiness JSON-LD** (name,
  Nairobi address, phone, socials, real price range) so even the pre-JavaScript
  HTML identifies the business.
- `src/components/site/SEO.tsx` — OG image now self-hosted
  (`public/og-image.jpg`, copied from `src/assets/hero.jpg`); `og:url` now uses
  the canonical URL.
- `public/sitemap.xml` — refreshed lastmod dates.

## Migration steps — do these in order

### Before switching the domain

1. **Export WordPress blog post URLs.** In WP admin: Tools → Export, or just
   list every published post's URL. Any post with traffic needs a 301 in
   `vercel.json` (add entries like the existing ones). Old posts you don't map
   will 404 and lose their rankings.
2. **Fix the prerender** (recommended, not blocking): run `npm run build`
   locally **with the backend API running** and check that
   `dist/about/index.html` contains real `<h1>`/`<p>` content and meta tags.
   If it still captures empty pages, the puppeteer wait condition in
   `scripts/prerender.mjs` needs attention. Google *can* index JS-rendered
   pages, so this is a quality boost, not a blocker.
3. **Deploy the app** with the changes in this repo and test the redirects on
   the preview URL (e.g. `<preview>/contact-us` should 301 to `/contact`).

### The switchover

4. In Vercel: add `fiestahouseattire.com` (and `www.`) as the app project's
   domain. Vercel will show the DNS records to set.
5. At the domain registrar / current DNS host: point the apex A/CNAME records
   at Vercel as instructed. WordPress stops receiving traffic the moment DNS
   propagates.
6. **Do not delete the WordPress hosting yet.** Keep it for 1–2 months as a
   fallback and content reference.

### Right after switchover

7. **Search Console:** the domain property is currently verified via a
   WordPress meta tag, which disappears with WordPress. Re-verify — DNS
   verification (TXT record) is best because it survives any future site
   changes. Then submit `https://fiestahouseattire.com/sitemap.xml`.
8. Spot-check the old URLs in an incognito window:
   `/gowns-for-hire`, `/contact-us`, `/blog-2`, one portfolio slug — each must
   301 to the right page.
9. Watch Search Console's Coverage report for 404 spikes over the next two
   weeks — each 404 with impressions means a WordPress URL that needs a
   redirect added to `vercel.json`.

### Within a month

10. Update Google Business Profile, Instagram bio, Facebook page, and the
    Play Store app listing to the apex URL (no `app.`).
11. Blog posts from the app's CMS are **not in the sitemap** (it's static).
    Either regenerate it when publishing, or extend
    `scripts/generate-image-sitemap.mjs`'s approach to pull post slugs from the
    backend.
12. Once Search Console shows the new site indexed and stable (4–8 weeks),
    cancel WordPress hosting.

## Ranking expectations

A migration done with proper 301s typically sees a small dip for 2–6 weeks,
then recovery. The old site's keyword-rich portfolio pages
("baby bump photoshoot Nairobi", "maternity gowns for hire in Nairobi") all
redirect to `/portfolio` or `/maternity-gowns` — consider recreating the best
of those as dedicated pages/posts in the app over time, since a 20-to-1
redirect keeps *some* equity but a real page targeting the same phrase keeps
more.
